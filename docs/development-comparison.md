# MoonRelay 开发版与 rsync、rclone SFTP 的对照

本页展示 **未发布的 0.5.0 开发快照**，不是当前可下载的 0.4.0，也不代表最新本地候选。发布版结果见[0.4.0 与 scp、rsync 对照](transfer-comparison.md)。

在这个环境中，MoonRelay 的小目录传输快于本页 rclone SFTP 配置，慢于 rsync；大文件首次下载慢于两者，首次上传介于两者之间。已完成任务重跑时两者均更快。下载中断后的重启阶段，MoonRelay 耗时较低；上传恢复仍慢于 rsync。各场景、方向分别比较，不作综合排名。

## 耗时与差距

单位秒，**原生命令 + 独立完整文件集 / SHA-256 核验**的中位数（最小–最大）。下载每工具每场景10次，上传5次；只比较内容和相对路径。中断后重启行仅统计重启阶段。

## 使用成本与适用范围

MoonRelay 需要两端安装兼容的程序。它的用途是让 MoonBit 应用直接调用传输、进度与恢复接口；本页没有证明吞吐优势或同等断电持久性。目录逐文件完成，不提供整树原子发布、删除同步或云存储后端。

小目录传输完成后，MoonRelay 本组唯一 inode 逻辑占用约2.009 MiB，rsync/rclone约2.000 MiB；128 MiB大文件完成后，三者逻辑占用约128 MiB。该开发版采用线性存储；发布版0.4.0保留分块与最终文件，完成后约占两份空间，两者不能混用。逻辑占用不等于物理峰值。

需要增量备份、镜像及文件属性保留时，可查看 [rsync 手册](https://download.samba.org/pub/rsync/rsync.1)；rclone 的完整 SFTP 功能与配置见 [官方文档](https://rclone.org/sftp/)。这里的 rclone 使用外部 OpenSSH 以统一加密和连接配置，不能代表其默认 Go SSH 路径或其他后端。

## 条件与数值核对

2026-10-19，macOS ARM64 ↔ Linux x86_64，同一确定性数据、预热源、warm SSH ControlMaster、AES128-GCM、关闭压缩；新建目标，交错运行，背景负载未隔离，未清空系统缓存。完整文件身份见 JSON。

- 大文件128 MiB；目录32个64 KiB文件、四个子目录及一个空目录。
- rsync客户端3.5.0、服务端3.2.7，参数 `-rt --partial-dir=.rsync-partial --no-whole-file --no-compress --stats`，保留正常增量与部分文件能力。
- rclone1.75.2，SFTP over external OpenSSH，`--transfers 4 --checkers 8 --sftp-concurrency 64 --sftp-chunk-size 32Ki`，运行前确认远端MD5/SHA1能力。
- 中断场景统一经过8 MiB/s计量转发器，在32 MiB加密SSH流量时终止客户端进程组并断开payload连接；实际已提交前缀可能不同。恢复流量和部分文件不能等同持久偏移或同等恢复策略。
- 每条完成记录都通过独立完整SHA-256和文件集核验。该共同核验没有把工具原有同步策略改成一致，也不是它们各自默认体验的耗时。
- 同环境数据不能排除网络、调度和执行时刻差异，不据此保证每次更快。
